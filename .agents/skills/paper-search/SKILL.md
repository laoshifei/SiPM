# paper-search

## 文献库位置

优先使用用户本次指定的路径，其次使用调用项目 AGENTS.md 中的“文献库路径”。没有配置时询问实际路径，不猜测。技能正文不固定机器路径；迁移时更新调用项目的路径配置。

确认目录中实际存在 AGENTS.md、index.md、sources/ 和 raw/。读取文献库的 AGENTS.md 与 index.md；文献库规则约束对库内资料的操作，当前项目中的研究或写作仍遵守调用项目规则。

## 检索与核对

1. 根据当前问题确定研究对象、用途、关键词及中英文别名。涉及会改变选材的研究重点而信息不足时，仅澄清必要问题。
2. 优先查看 vocabulary.json、topic-index.md 和 review-index.md；它们用于导航。回到相关 sources/ 完整笔记，以及 global-review.md 中的原始答复，核对对象、条件和实际采用范围。
3. 库内有检索脚本时复用下面的只读命令；先将 PAPER_LIBRARY_ROOT 设置为已确认的非空库根目录。主题关联只覆盖已有显式链接，不能作为全文检索的替代。

```bash
python3 "$PAPER_LIBRARY_ROOT/.agents/skills/paper-read/scripts/knowledge_index.py" --root "$PAPER_LIBRARY_ROOT" search-topic "关键词" --limit 10
python3 "$PAPER_LIBRARY_ROOT/.agents/skills/paper-read/scripts/knowledge_index.py" --root "$PAPER_LIBRARY_ROOT" search-review "关键词" --context --limit 10
```

4. 用 rg 补查 sources/、concepts/、methods/、synthesis/ 和 global-review.md。脚本缺失或检索无命中时，改用可用的文本工具，说明检索范围和限制；不要把无命中说成文献不存在。
5. 从完整笔记提取与问题相关的论点、数值、方法与适用条件。明确区分论文作者的结论、AI解释和用户实际认可的意见；局部认可不等于整篇通过，旧历史状态不能盖过后续确认。
6. 需要核实关键数字、公式、图表或拟用于写作的重要主张时，定向查看对应原PDF及可验证的已有缓存。只查笔记时写明“据既有精读笔记”，实际查阅PDF时注明页码和范围；工具缺失或不可辨时保留待核状态，不声称已核原文或已读全文。
7. 引用关系、主题相近和科学支持是不同事实。支持、扩展或矛盾必须有具体双方论点、出处及条件。被引原文未查阅时明确写“据当前论文转述”，不把书目条目当作独立精读结果。

## 输出

按当前问题组织相关结果，数量遵守用户要求。每篇提供可核实的题目、作者、年份和DOI（未核实则说明），真实的笔记与原文链接、PDF页码及图表／公式位置、相关内容及适用范围、已有采用意见和剩余缺口。页码从本地PDF第1页计。

说明本轮证据核验层级和内容适合用于何种论证；涉及未获支持或相反结果时保留其出处，不拼接不同实验条件或将模型输入写成测量结论。科研与写作判断仍由当前问题和证据决定，不替用户指定研究主线。

## 操作范围

本技能只读共享文献库：不修改原PDF、笔记、索引、日志、队列或审核状态，不运行索引重建写入命令。库内 `.cache/` 也保持只读；新提取的文本、页面图及其他临时文件放在调用项目的 `.cache/paper-search/` 或系统临时目录。文献库维护须作为另行明确授权的任务处理，不由本技能实施。

默认只用本地资料，不联网、下载、安装软件或递归精读引用文献。权限或工具阻碍时如实说明；技能本身不授予跨目录访问权限。

根据用户要求在调用项目中保存证据表或写作内容，保留出处和审核范围；共享的是已保存文件，其他会话中未保存的讨论不自动成为依据。
